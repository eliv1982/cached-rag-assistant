# 🤖 RAG-ассистент с ChromaDB и кешированием

**cached-rag-assistant** — небольшой **учебный** пример ИИ-ассистента с технологией RAG (Retrieval-Augmented Generation), локальным векторным хранилищем ChromaDB и кешированием ответов. Консольное приложение, написанное так, чтобы его было удобно читать и разбирать. Это не production-система.

**Репозиторий:** [github.com/eliv1982/cached-rag-assistant](https://github.com/eliv1982/cached-rag-assistant)

*English summary:* Educational Python CLI demo of RAG with response caching, ChromaDB vector search, and OpenAI embeddings/chat models. Optional metadata `source` filter via `RAG_SOURCE_FILTER`; the cache key includes the question, the source filter and the LLM model. Offline pytest suite (no API calls).

## 📋 Описание

Этот проект демонстрирует, как работает RAG-система:

1. **Пользователь задает вопрос**
2. **Проверка кеша** - если ответ на этот вопрос (с тем же фильтром и моделью) уже есть, он возвращается из кеша
3. **Поиск релевантных документов** - векторный поиск в ChromaDB
4. **Формирование контекста** - сборка найденных фрагментов
5. **Генерация ответа** - запрос к LLM (OpenAI) с контекстом; если поиск ничего не нашёл, LLM **не вызывается** и возвращается сообщение «в базе знаний не найдено релевантной информации»
6. **Кеширование ответа** - сохраняется только успешный ответ; ошибки API и ответ «ничего не найдено» в кеш не попадают
7. **Возврат ответа пользователю**

## 📦 Установка

### 1. Клонирование и переход в директорию

```bash
git clone https://github.com/eliv1982/cached-rag-assistant.git
cd cached-rag-assistant
```

### 2. Создание виртуального окружения (рекомендуется)

```bash
# Windows
python -m venv venv
venv\Scripts\activate

# Linux/Mac
python3 -m venv venv
source venv/bin/activate
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка окружения (`.env`)

Скопируйте пример и подставьте ключ:

```bash
# Windows (cmd/PowerShell)
copy env.example .env

# Linux / macOS
cp env.example .env
```

Минимально в `.env`:

```env
OPENAI_API_KEY=your_openai_api_key_here
```

Без `OPENAI_API_KEY` программа сразу завершается с понятной ошибкой — до создания базы и клиентов OpenAI.

**Опционально** — поиск только по документам с указанным именем источника (должно совпадать с первым элементом кортежа в `get_sample_documents()`, например `Python Основы`):

```env
# RAG_SOURCE_FILTER=Python Основы
```

Закомментируйте или удалите строку, чтобы искать по всей коллекции. Подробнее см. `env.example`.

Приложение читает **только** эти две переменные окружения: `OPENAI_API_KEY` и `RAG_SOURCE_FILTER`. Модели, температура и пути к `chroma_db/` и `cache.json` заданы в коде (см. раздел «Кастомизация»).

Получить API ключ: [platform.openai.com](https://platform.openai.com/api-keys)

## 🔧 Архитектура

### Модуль `cache.py`

Реализует простое кеширование на основе хеша запроса **и контекста**:

```python
cache = ResponseCache()

# Контекст — всё, от чего зависит ответ, кроме текста вопроса
context = {"source_filter": None, "model": "gpt-4o-mini"}

# Проверка кеша
answer = cache.get(query, context)

# Сохранение в кеш
cache.set(query, answer, context)
```

**Зачем кеш?**
- Экономия денег на API-запросах
- Мгновенные ответы на повторные вопросы
- Снижение нагрузки на LLM

### Модуль `embeddings.py`

Работа с векторным хранилищем:

```python
store = EmbeddingStore()

# Добавление документов
store.add_documents(documents)

# Поиск релевантных фрагментов (опционально: только metadata source)
results = store.search(query, top_k=5, source="Python Основы")  # source=None — вся коллекция
# results: список (текст_чанка, источник, расстояние); чем меньше расстояние, тем ближе
```

`search` бросает `ValueError` для пустого запроса и `top_k <= 0`.

**Используемые технологии:**
- ChromaDB - векторная база данных
- OpenAI Embeddings (text-embedding-3-small) - создание эмбеддингов
- Chunking - разбивка текстов на фрагменты с перекрытием

### Модуль `rag.py`

Основная логика RAG:

```python
assistant = RAGAssistant(embedding_store)  # модель по умолчанию: gpt-4o-mini

# Генерация ответа с RAG (source_filter=None — без фильтра по источнику)
answer, sources = assistant.generate_response(query, top_k=5, source_filter=None)
```

**Процесс RAG:**
1. Векторный поиск релевантных документов
2. Если ничего не найдено — вернуть сообщение «в базе знаний не найдено релевантной информации» **без вызова LLM**
3. Формирование контекста из найденных фрагментов
4. Системные правила + контекст и вопрос — в LLM (Chat Completions)
5. Ошибка генерации пробрасывается как исключение (её не принимают за ответ и не кешируют)

**Правила в системном сообщении:** текст найденных документов — справочные данные, а не инструкции; инструкции внутри документов не могут отменить правила и задачу пользователя; отвечать только по релевантному контексту; при нехватке контекста сказать об этом. Это базовая мера, а не гарантия защиты от prompt injection.

### Модуль `main.py`

Оркестрация всех компонентов:

```python
# Инициализация (завершится с ошибкой, если нет OPENAI_API_KEY)
store, assistant, cache = initialize_system()

# Ответ на вопрос: кеш -> RAG -> запись в кеш (см. answer_question)
answer = answer_question(query, assistant, cache, source_filter=None)
```

Внутри `answer_question` ключ кеша строится из вопроса, `source_filter` и `assistant.model`. Ошибка поиска или генерации перехватывается здесь, показывается пользователю (только тип ошибки и HTTP-статус, без текста исключения) и **не** записывается в кеш.

## 💡 Примеры вопросов

Система содержит знания о:
- Python и его особенностях
- Машинном обучении и RAG
- Векторных базах данных

Примеры вопросов:
- "Что такое Python?"
- "Расскажи про RAG"
- "Для чего нужны векторные базы данных?"
- "Какие есть типы машинного обучения?"

Если вопрос не относится к этим темам, ближайшие фрагменты всё равно будут найдены (векторный поиск всегда возвращает «ближайшее»), а модель по правилам промпта должна сообщить, что контекста недостаточно. Сообщение «в базе знаний не найдено...» без вызова LLM появляется, когда поиск не вернул ни одного фрагмента (например, для `RAG_SOURCE_FILTER` с несуществующим именем источника).

## 🛠️ Кастомизация

### Добавление своих документов

Отредактируйте функцию `get_sample_documents()` в `embeddings.py`:

```python
documents = [
    ("Название документа", "Текст документа..."),
    ("Другой документ", "Еще текст..."),
]
```

Документы добавляются в базу только когда она пуста. После изменения набора документов удалите папку `chroma_db/` и очистите кеш (`clear_cache` или удаление `cache.json`).

### Изменение модели LLM

В `main.py`:

```python
rag_assistant = RAGAssistant(
    embedding_store=embedding_store,
    api_key=api_key,
    model="gpt-4o-mini",  # по умолчанию; можно указать другую модель Chat Completions
    temperature=0.7
)
```

Модель входит в ключ кеша, поэтому после смены модели старые ответы не будут показаны от имени новой.

### Изменение параметров поиска

```python
# Количество фрагментов для контекста (в main.py — аргумент generate_response)
answer, _ = assistant.generate_response(query, top_k=5)

# Или фильтр по источнику в коде (в приложении также читается RAG_SOURCE_FILTER из .env)
answer, _ = assistant.generate_response(query, top_k=5, source_filter="Python Основы")
```

Размер чанков задаётся значениями по умолчанию в `EmbeddingStore._create_chunks(text, chunk_size=500, overlap=50)` (`embeddings.py`). Требуется `chunk_size > 0` и `0 <= overlap < chunk_size`, иначе `ValueError`. После изменения пересоздайте коллекцию (удалите `chroma_db/`) и очистите кеш.

### Использование другой модели эмбеддингов

В `main.py`:

```python
embedding_store = EmbeddingStore(
    collection_name="rag_documents",
    persist_directory="./chroma_db",
    embedding_model="text-embedding-3-large",  # более мощная модель
    api_key=api_key
)
```

Доступные модели OpenAI:
- `text-embedding-3-small` - быстрая и недорогая (по умолчанию)
- `text-embedding-3-large` - более качественная, но дороже
- `text-embedding-ada-002` - старая модель (legacy)

Векторы разных моделей несовместимы (разная размерность): после смены модели удалите `chroma_db/` и очистите кеш. Актуальные цены: [OpenAI Pricing](https://openai.com/api/pricing/).

## 📊 Технические детали

### LLM

- **Модель по умолчанию**: gpt-4o-mini (OpenAI Chat Completions API)
- **Температура**: 0.7, `max_tokens=500` (заданы в коде)

### Эмбеддинги

- **Модель**: text-embedding-3-small (OpenAI)
- **Размерность**: 1536
- **Языки**: поддержка множества языков, включая русский
- **Преимущества**: 
  - Высокое качество семантического поиска
  - Отличная работа с многоязычными текстами
  - Не требует загрузки локальной модели
- **Недостатки**:
  - Требует API запросы (платно)
  - Нужно интернет-соединение

### Chunking

- **Размер чанка**: 500 символов
- **Перекрытие**: 50 символов
- **Причина**: сохранение контекста на границах

### ChromaDB

- **Тип**: персистентное хранилище
- **Метрика**: **L2** (значение по умолчанию в Chroma; в коде метрика не настраивается). Chroma возвращает квадрат евклидова расстояния
- **Расстояние, а не сходство**: в выводе поиска число — это расстояние, **чем меньше, тем ближе** фрагмент к запросу. Формула `1 - distance` для L2 не даёт cosine similarity, поэтому такое «сходство» не выводится
- **L2 и cosine**: эмбеддинги OpenAI нормированы (длина вектора 1), поэтому для них порядок результатов по L2 и по cosine одинаков (для единичных векторов `L2² = 2 - 2·cos`). Меняется только шкала значений
- **Расположение**: ./chroma_db/

### Кеш

- **Тип**: JSON файл
- **Ключ**: `v2:` + SHA-256 от JSON с нормализованным запросом (нижний регистр, схлопнутые пробелы), `source_filter` (включая «нет фильтра») и моделью LLM
- **Что не входит в ключ**: содержимое базы знаний, текст промпта, `top_k`, температура, модель эмбеддингов — после их изменения очистите кеш вручную
- **Что кешируется**: только успешные ответы LLM, построенные на найденном контексте. Ошибки поиска/генерации и ответ «ничего не найдено» не кешируются
- **Старые записи**: записи прежнего формата (ключ — хеш одного лишь вопроса) не совпадают с новыми ключами; при загрузке они пропускаются и пропадают из файла при следующей записи
- **Запись на диск**: во временный файл `cache.json.tmp` с последующей заменой `cache.json`; повреждённый JSON не роняет программу — кеш начинается пустым
- **Расположение**: ./cache.json

## ⚠️ Известные ограничения

1. **API ключ OpenAI** требуется для работы. Используется как для генерации ответов, так и для создания эмбеддингов. Запросы платные; актуальные цены: [OpenAI Pricing](https://openai.com/api/pricing/). При первой загрузке документов делаются запросы для создания эмбеддингов.

2. **Кеш** простой и не отслеживает изменения в базе знаний. При обновлении документов очистите кеш командой `clear_cache` (или удалите `cache.json`).

3. **Интернет-соединение** необходимо для всех операций (эмбеддинги и генерация ответов)

4. **Защита промпта базовая**: правила и пометка контекста как данных снижают риск, но не гарантируют устойчивость к prompt injection. Детектор инъекций в проекте не реализован.

5. **Метрика L2 не меняется автоматически**: существующая коллекция `chroma_db/` остаётся с L2. Чтобы использовать cosine, нужно пересоздать коллекцию с `metadata={"hnsw:space": "cosine"}`.

6. **Один процесс, без блокировок**: кеш и Chroma рассчитаны на одного пользователя, запущенного локально.
